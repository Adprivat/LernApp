  <action>
Import `{ getErrorMessage }` from `@/lib/errorHandler`.

AdminPage has a unique situation: it uses `confirm()` (not `alert()`) for destructive action confirmation. `confirm()` is acceptable for admin confirmation dialogs — it's not an error display pattern. The issue is that admin actions (deleteUser, resetScore, toggleAdmin) have NO error handling at all — failures are silent.

Fix these issues:

1. **toggleAdmin() lines ~57-63** — No error handling on the update call.
   Add error check: `const { error } = await supabase.from('profiles').update(...).eq('id', profile.id);`
   If `error`, log: `console.error('toggleAdmin failed:', error.message);`

2. **deleteUser() lines ~66-70** — No error handling on the delete call.
   Add error check: `const { error } = await supabase.from('profiles').delete().eq('id', profile.id);`
   If `error`, log: `console.error('deleteUser failed:', error.message);`

3. **resetScore() lines ~73-79** — No error handling on the update call.
   Add error check: `const { error } = await supabase.from('profiles').update(...).eq('id', profile.id);`
   If `error`, log: `console.error('resetScore failed:', error.message);`

4. **fetchStats() lines ~45-49** — Promise.all destructuring assumes all three queries succeed.
   Wrap in try/catch: `try { ... } catch (err: unknown) { console.error('fetchStats failed:', getErrorMessage(err)); }`

Note: AdminPage does NOT have `catch (err: any)` currently — the issue is missing error handling entirely. Adding console.error for admin-only operations is appropriate (admin sees dev tools). No need to add UI error display since admin users can check console.
